# Rivet C ABI (librivet, ABI version 1)

> **Status:** Active
> **Created:** 2026-09-29
> **Last Updated:** 2026-09-29
> **Affected Versions:** 0.2.0 and later
> **Owner:** Project maintainer
> **Affected Components:** ffi, library, sessions, registry, language

## Summary

`librivet` exposes the Rivet runtime to any language that can call C. It is **JSON in, JSON out** over
NUL-terminated UTF-8 strings: inputs are [InputEnvelopes](api-2026-0006-envelopes.md#inputenvelope), outputs are
[ResponseEnvelopes](api-2026-0006-envelopes.md#responseenvelope-unary-answer-or-the-terminal-record-of-a-stream)
and stream records. Three opaque handle types exist, and no callback crosses the boundary.

```text
 ┌─────────────────────────── C / Python / Go host ───────────────────────────┐
 │ rivet_runtime_new(opts) ──▶ RivetRuntime* ──┬─ rivet_request(input) ─────────▶ char* envelope
 │                                             ├─ rivet_call_start(input) ──▶ RivetCall* ─ next/send/finish/cancel/free
 │                                             └─ rivet_load(path, alias) ──▶ RivetModule* ─ operations/call/call_start/free
 │ rivet_highlight(src, fmt) ─────────────────────────────────────────────────▶ char* tokens
 │ rivet_string_free(char*)   rivet_abi_version()   rivet_version()                                     │
 └──────────────────────────────────────┬──────────────────────────────────────┘
                                        │ extern "C" (ffi/src/lib.rs shims, crate rivet-ffi)
                                        ▼
            src/orchestrator/setup_ffi.rs (the `ffi` surface: guards, handle table, JSON) ──▶ rivet::Runtime
```

Artifacts: `librivet.dylib` (macOS) or `librivet.so` (Linux), `librivet.a`, `ffi/include/rivet.h`, and a
`rivet.pc` rendered from `ffi/rivet.pc.in`. Windows is not supported in 0.2.0.

Captured with `cargo build --release -p rivet-ffi` at `main` `e7ed8ed` (macOS 26.4, Apple clang 21). Request and
trace IDs differ on every run; `rivet_version()` printed `0.1.0` because the workspace version is bumped by the
release commit (it reads `0.2.0` in the release build).

## Audience and Stability

C, C++, Python (`ctypes`/`cffi`), Go (`cgo`) and other FFI hosts. The ABI is **version 1**
(`rivet_abi_version() == 1`). A function is never removed or changes its signature within ABI 1; new functions
may be added. JSON payloads follow the envelope stability rules of API-2026-0006.

## Authentication

None at the ABI: the host process is the principal (`local`), as for the Rust library. What an operation may
touch is decided by the policy of the runtime options (`policy_file`, `policy_json`, `ceiling_json`, or a
`policy.json` discovered beside `file`); without one, everything is denied except pure operations. See
[SEC-2026-0001](../security/sec-2026-0001-policy-and-sandbox-model.md).

## Endpoints or Events

### Types and status codes

| Name | Kind | Meaning |
|---|---|---|
| `RivetStatus` | enum | `RIVET_OK = 0`, `RIVET_ERROR = 1` |
| `RivetRuntime` | opaque handle | A loaded bundle and its async runtime. **Thread-safe.** |
| `RivetCall` | opaque handle | One running call (stream, live input). **One thread at a time.** |
| `RivetModule` | opaque handle | A `.rivet` file loaded into a runtime. **Thread-safe.** |

Handles are opaque tokens that are never dereferenced: a table maps each live token to its object, so a
freed, foreign or wrong-kind handle is refused with `validation.ffi_argument` instead of undefined behaviour.

### The 18 functions

| # | Function | Returns | Caller frees | Notes |
|---|---|---|---|---|
| 1 | `uint32_t rivet_abi_version(void)` | `1` | — | Check before any other call |
| 2 | `const char *rivet_version(void)` | static `"0.2.0"` | **no** | The only string you must not free |
| 3 | `RivetStatus rivet_runtime_new(const char *options_json, RivetRuntime **out_rt, char **error_json)` | status | `*error_json` | Options below; on error `*error_json` (if not NULL) is an envelope |
| 4 | `RivetStatus rivet_runtime_free(RivetRuntime *rt)` | status | — | Cancels and drains in-flight calls (5 s grace); second free → `RIVET_ERROR` |
| 5 | `char *rivet_request(RivetRuntime *rt, const char *input_json)` | envelope | yes | Blocking; always an envelope, errors included |
| 6 | `RivetCall *rivet_call_start(RivetRuntime *rt, const char *input_json)` | handle | `rivet_call_free` | **Never NULL**: a failed start yields its error record on the first `next` |
| 7 | `char *rivet_call_next(RivetCall *call, int64_t timeout_ms)` | record / `{"type":"timeout"}` / NULL | yes | NULL after the terminal record; negative timeout waits |
| 8 | `char *rivet_call_send(RivetCall *call, const char *data_json)` | ack or envelope | yes | One live input item (`receives` operations) |
| 9 | `char *rivet_call_finish_input(RivetCall *call)` | ack or envelope | yes | Closes live input |
| 10 | `RivetStatus rivet_call_cancel(RivetCall *call)` | status | — | Records end with `status: "cancelled"` |
| 11 | `RivetStatus rivet_call_free(RivetCall *call)` | status | — | A running call is cancelled first (5 s grace); second free → `RIVET_ERROR` |
| 12 | `char *rivet_highlight(const char *source, const char *format)` | tokens | yes | `format`: `"json"` (NULL), `"html"`, `"ansi"`; no runtime needed |
| 13 | `RivetStatus rivet_load(RivetRuntime *rt, const char *path, const char *alias_or_null, RivetModule **out_module, char **error_json)` | status | `*error_json` | Loads a file below the runtime root; alias = file stem when NULL |
| 14 | `char *rivet_module_operations(RivetModule *module)` | JSON array | yes | `[{id, operation, name, description, emits, receives}]` |
| 15 | `char *rivet_module_call(RivetModule *module, const char *id, const char *data_json)` | envelope | yes | Short ID (`"get"`); envelope names `users.get`; NULL data = `{}` |
| 16 | `RivetCall *rivet_module_call_start(RivetModule *module, const char *id, const char *data_json)` | handle | `rivet_call_free` | Like `rivet_call_start` |
| 17 | `RivetStatus rivet_module_free(RivetModule *module)` | status | — | Frees the handle; the module stays loaded in its runtime |
| 18 | `RivetStatus rivet_string_free(char *s)` | status | — | NULL → `RIVET_OK`; a pointer librivet did not return, or already freed → `RIVET_ERROR` |

## Request Format

### Runtime options (`rivet_runtime_new`)

One JSON object. Exactly one bundle form is used:

| Key | Type | Meaning |
|---|---|---|
| `file` | string | Entry `.rivet` file (its directory is the root); without a policy option, a `policy.json` beside it is discovered, as on the CLI |
| `source` + `path` + `root` | strings | In-memory source text, the name used in diagnostics, and the runtime root |
| `root` (alone) | string | A runtime with no entry file (deny-by-default policy unless one is given); add modules with `rivet_load` |
| `policy_file` / `policy_json` | string path / JSON object | The policy (schema v1); at most one of the two. Default: discovery as above, else deny everything but pure operations |
| `ceiling_json` | JSON object | A host ceiling that can only narrow the policy |
| `pretty` | bool | Indent every returned envelope and record |

An unknown key is refused:

```text
options-error {"request_id":"","trace_id":"","operation":null,"type":"result","status":"error","data":null,"error":{"kind":"validation","code":"validation.ffi_argument","message":"unknown option `colour` (expected one of file, source, path, root, policy_file, policy_json, ceiling_json, pretty)","retryable":false,"details":{"argument":"colour"}},"effects":"none","data_count":0}
```

### Input (`rivet_request`, `rivet_call_start`)

An [InputEnvelope](api-2026-0006-envelopes.md#inputenvelope): `{operation, data?, deadline_ms?, restrict?,
pretty?}`. The deprecated `{id, params}` keys still work in 0.2.x (no signal is emitted over the ABI).

## Response Format

### Envelopes and records

```text
request {"request_id":"req_01aaa1efc5","trace_id":"tr_01aaa1efc5","operation":"demo.add","type":"result","status":"ok","data":5,"error":null,"effects":"none","data_count":0}
record {"request_id":"req_0428dc76e4","trace_id":"tr_0428dc76e4","operation":"events.count","type":"data","seq":1,"data":1,"error":null}
record {"request_id":"req_0428dc76e4","trace_id":"tr_0428dc76e4","operation":"events.count","type":"data","seq":2,"data":2,"error":null}
record {"request_id":"req_0428dc76e4","trace_id":"tr_0428dc76e4","operation":"events.count","type":"data","seq":3,"data":3,"error":null}
record {"request_id":"req_0428dc76e4","trace_id":"tr_0428dc76e4","operation":"events.count","type":"result","seq":4,"status":"ok","data":{"count":3},"error":null,"effects":"none","data_count":3}
```

(Output of `examples/c/demo.c`; the label before each line is printed by the example.)

### Live input acks

```text
send   {"session_id":"ses_022b6958c2","accepted_seq":1,"input_closed":false}
send   {"session_id":"ses_022b6958c2","accepted_seq":2,"input_closed":false}
finish {"session_id":"ses_022b6958c2","accepted_seq":null,"input_closed":true}
```

### Module operations

```text
operations [{"id":"get","operation":"users.get","name":"users.get","description":"One user by id.","emits":false,"receives":false},{"id":"list","operation":"users.list","name":"users.list","description":"The first two users (calls inside a module use its own IDs).","emits":false,"receives":false}]
call {"request_id":"req_01b37c0705","trace_id":"tr_01b37c0705","operation":"users.get","type":"result","status":"ok","data":{"id":42,"name":"Hello, user 42"},"error":null,"effects":"none","data_count":0}
```

### Highlight

`json` is one `{line, col, len, class, text}` object per line (1-based, columns in characters); `html` is a
`<pre class="rv-source">` block with `<span class="rv-CLASS">`; `ansi` uses terminal colours. After a syntax
error the `json` output keeps the tokens before it and ends with an error-envelope line.

### Call handle lifecycle

```text
 rivet_call_start ─▶ STARTED
    │ next(t) ─▶ {"type":"data",…}      (repeat)         send()/finish_input() allowed while running
    │ next(t) ─▶ {"type":"timeout"}     nothing within t ms; poll again
    │ next(t) ─▶ {"type":"result",…}    terminal record (ok | error | cancelled)
    │ next(t) ─▶ NULL                   DONE (every later next is NULL)
    │ cancel() ─▶ the next records end with {"type":"result","status":"cancelled"}
    └ free()   ─▶ running: cancel + 5 s bounded cleanup ─▶ FREED ; free again ─▶ RIVET_ERROR
```

A call handle is a connection-owned session of the shared session driver: it does not count toward the
8-sessions-per-principal limit, but the **60 s idle lease** applies, so a call not read for 60 s is cancelled.
`rivet_call_next` long-polls in slices of at most 5 s. `rivet_call_cancel` cancels the session and the request.

### Module handle lifecycle

```text
 rivet_load(rt, "./users.rivet", NULL) ─▶ LOADED (alias "users"; the runtime catalog gains users.*)
    ├ rivet_module_operations / rivet_module_call / rivet_module_call_start
    ├ rivet_request(rt, {"operation":"users.get"})  also works (namespaced ID)
    └ rivet_module_free ─▶ handle FREED, module stays loaded ; free again ─▶ RIVET_ERROR
 rivet_load of an alias already loaded ─▶ RIVET_ERROR + check.import_duplicate envelope
```

A load swaps in a new catalog snapshot; in-flight calls keep the snapshot they started with.

## Error Format

Every failure is a ResponseEnvelope with `status: "error"` (never a crash). ABI-specific codes:

| Code | Kind | Cause | Example `message` |
|---|---|---|---|
| `validation.ffi_argument` | validation (exit-equivalent 2) | NULL or non-UTF-8 argument; unknown option; unknown highlight format; unknown, freed or wrong-kind handle | ``"`input_json` is NULL"``, `"unknown or already freed RivetRuntime handle"` |
| `internal.panic` | internal | A Rust panic caught at the boundary (`catch_unwind`) | — |
| `validation.input_envelope` | validation | The input is not a JSON object / not JSON | `"the input envelope is not valid JSON: key must be a string at line 1 column 2"` |

Captured misuse (a scratch program linked against `librivet.dylib`):

```text
null-options          {…"code":"validation.ffi_argument","message":"`options_json` is NULL",…,"details":{"argument":"options_json"}}
missing-file          {…"kind":"not_found","code":"not_found.source","message":"cannot read missing.rivet: No such file or directory (os error 2)",…}
null-input            {…"code":"validation.ffi_argument","message":"`input_json` is NULL",…}
highlight-bad-format  {…"operation":"rivet.highlight",…"code":"validation.ffi_argument","message":"unknown format `svg` (expected json, html or ansi)",…}
failed-start          {…"operation":"nope",…"code":"not_found.operation","message":"no operation `nope`",…}   then NULL
after-runtime-free    {…"code":"validation.ffi_argument","message":"unknown or already freed RivetRuntime handle",…}
free-foreign 1        rivet_string_free(pointer not from librivet) == RIVET_ERROR
free-null 0           rivet_string_free(NULL) == RIVET_OK
```

## Rate Limits

The runtime's policy `limits` and session limits apply; see API-2026-0005 kind `limit`.

## Versioning and Deprecation

`RIVET_H` declares ABI version 1. Additive changes keep version 1; a breaking change to `rivet.h` bumps
`rivet_abi_version()`. `rivet_version()` follows the workspace version (`0.2.0`). The header is generated by
`cbindgen` from `ffi/src/lib.rs` and checked in; do not edit it by hand.

## Examples

### Linking (as recorded)

```text
 macOS  shared  cc app.c -I ffi/include -L target/release -lrivet -Wl,-rpath,$PWD/target/release -o app
        static  cc app.c -I ffi/include target/release/librivet.a \
                   -framework Security -framework CoreFoundation -liconv -lc -lm -o app_static
 Linux  shared  cc app.c -I ffi/include -L target/release -lrivet -Wl,-rpath,$PWD/target/release -o app
        static  cc app.c -I ffi/include target/release/librivet.a -lgcc_s -lutil -lrt -lpthread -lm -ldl -lc -o app_static
 pkg-config     python3 ffi/render_pc.py --prefix /usr/local > rivet.pc
                cc app.c $(pkg-config --cflags rivet) $(pkg-config --libs --static rivet)
```

The static library list is `cargo rustc -p rivet-ffi --release --crate-type staticlib -- --print
native-static-libs` (also `rivet.pc` `Libs.private`). On macOS, build `librivet` and link the program with the
same `MACOSX_DEPLOYMENT_TARGET`, or `ld` prints `object file … was built for newer 'macOS' version (26.4) than
being linked (26.0)` for `ring`'s assembly objects; the program is still correct. The dylib install name is
`@rpath/librivet.dylib`. The Linux list is verified by CI (ubuntu-latest), not on a local host.

### Minimal C program

```c
#include <stdio.h>
#include <rivet.h>

int main(void) {
    RivetRuntime *rt = NULL;
    char *err = NULL;
    if (rivet_runtime_new("{\"file\":\"examples/ffi/app.rivet\"}", &rt, &err) != RIVET_OK) {
        fprintf(stderr, "%s\n", err);                 /* an error envelope */
        rivet_string_free(err);
        return 1;
    }
    char *out = rivet_request(rt, "{\"operation\":\"demo.add\",\"data\":{\"a\":2,\"b\":3}}");
    puts(out);                                        /* {"request_id":…,"status":"ok","data":5,…} */
    rivet_string_free(out);

    RivetCall *call = rivet_call_start(rt, "{\"operation\":\"events.count\",\"data\":{}}");
    char *rec;
    while ((rec = rivet_call_next(call, 5000)) != NULL) {   /* NULL after the result record */
        puts(rec);
        rivet_string_free(rec);
    }
    rivet_call_free(call);
    rivet_runtime_free(rt);
    return 0;
}
```

Full programs: `examples/c/demo.c` (request, pretty, stream, live input, cancel, highlight, double free) and
`examples/c/modules.c` (`rivet_load`, module calls); `make -C examples/c test` builds and runs them shared and
static. Python: `examples/python/rivet.py` (a ctypes wrapper declaring all 18 prototypes), `demo.py`, `modules.py`.

## Compatibility Notes

- Windows (`rivet.dll`) is not supported in 0.2.0.
- The `rivet-ffi` crate builds `cdylib` and `staticlib` only; its safety tests live in `ffi/src/tests.rs`
  (INC-2026-0010: an `rlib` output collided with `rivet-runtime`'s `librivet.rlib`).
- `cargo test` leaves the cdylib and staticlib under `target/<profile>/deps`
  ([TRBL-2026-0006](../troubleshooting/trbl-2026-0006-cargo-test-leaves-cdylib-and-staticlib-in-deps.md)); use
  `cargo build -p rivet-ffi` to get them in `target/<profile>`.
- Compared with the proposal sketch: the free functions return `RivetStatus` (so a double free is observable),
  `rivet_call_start` never returns NULL, and a NULL `data_json` means `{}`.
