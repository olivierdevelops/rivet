## Procedure


Tests executed (6):

- `conformance_operation_catalog::capabilities_builtin_reports_this_build` — G36/S102: `request rivet.capabilities` needs no policy.json and reports protocols, the sandbox backend for this OS, Stage C refusals and the version
- `conformance_operation_catalog::duplicate_id_rejects_the_whole_candidate` — S109: a second declaration of an existing ID (same file or another bundled file) rejects the whole candidate catalog with registry.duplicate_id and both spans; nothing is half-registered
- `conformance_operation_catalog::metadata_is_identical_on_every_surface` — S103/S104/S105: one multi-operation file publishes identical metadata through the library, CLI list/describe/outputs, HTTP /v1/operations and MCP tools/list
- `conformance_operation_catalog::private_helper_is_hidden_but_callable_in_bundle` — S109: a private helper is callable in-bundle but hidden from list/describe/outputs and refused by direct request, rivet.request, sessions.open, HTTP, MCP and the CLI
- `conformance_operation_catalog::reserved_rivet_ids_are_rejected` — IDs under `rivet.` are reserved for built-ins: syntax.reserved_id at the ID
- `conformance_operation_catalog::strict_docs_findings` — S119/S121/S123: `check --strict-docs` passes a fully documented catalog and reports each missing public description and undeclared fail code with its span (exit 2); private helpers are exempt

v0.1.0 run: `cargo test conformance_operation_catalog`.
