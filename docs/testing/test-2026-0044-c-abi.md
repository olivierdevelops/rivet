# T-11 — C ABI: shared and static librivet from C and Python (UC-06 / R13, R15)

> **Status:** Completed
> **Created:** 2026-09-29
> **Last Updated:** 2026-09-29
> **Affected Versions:** 0.2.0
> **Owner:** Project maintainer
> **Affected Components:** ffi

## Purpose

Show that `librivet` exports only `rivet_*` symbols, links shared and static from C, loads from Python ctypes, and drives requests, streams, live input and cancel; and that the checked-in header and pkg-config template match.

```text
  cargo build --workspace ─► librivet.dylib/.so  (install name @rpath)   librivet.a   ffi/include/rivet.h
                                   │                                         │
              examples/c/demo.c ───┴── shared ✔ ── static (Libs.private) ✔ ──┘
              examples/python/demo.py (ctypes) ✔
       rivet_request · rivet_call_start → next… → send → finish_input → cancel → free
```

## Preconditions

A clean checkout of `main` at commit `14750b8` (`14750b86a157d8fbaac7443201bc0eeb30747366`); Rust 1.90.0 from `rust-toolchain.toml`; `cargo build --workspace --all-features` run first so `librivet` exists for the FFI suites (TRBL-2026-0006); Python 3 and a C compiler on `PATH`. Fixtures are started in-process on `127.0.0.1:0` or in temporary directories by the tests; no external services.

## Test Environment

macOS 26.4.1 arm64 (aarch64-apple-darwin), Rust 1.90.0, Apple clang 21.0.0, Python 3.9.6, cbindgen 0.29.4 (local); GitHub Actions run 36505156729 at the same commit on ubuntu-latest and macos-latest (Rust 1.90.0, Python 3.12); Windows unsupported in 0.2.0 (INC-2026-0011).

## Test Data

The fixtures, bundles and goldens defined in `tests/conformance_ffi.rs` and the shared helpers under `tests/` (in-process servers, temporary directories, `tests/fixtures/`).

## Procedure

```sh
cargo build --workspace --all-features       # builds librivet for the suite (TRBL-2026-0006)
cargo test --all-features --test conformance_ffi
make -C examples/c OUT=/tmp/p3-leaks all
```

Tests executed (5):

- `conformance_ffi::t11_c_demo_shared_and_static` — T-11: the C demo linked shared and static prints envelopes, a stream (3 data + result), live input echoes, a cancelled call, highlight tokens, and refuses a double free
- `conformance_ffi::t11_exports_only_rivet_symbols` — T-11: librivet exports only rivet_* symbols (18), and on macOS its install name is @rpath/librivet.dylib
- `conformance_ffi::t11_header_matches_cbindgen` — T-11: the checked-in ffi/include/rivet.h is exactly what cbindgen generates from ffi/src/lib.rs
- `conformance_ffi::t11_pkg_config_template` — T-11: rivet.pc renders with the workspace version and this OS's Libs.private (the same list the C Makefile links statically)
- `conformance_ffi::t11_python_demo` — T-11: the Python ctypes demo requests, streams, sends live input, cancels and highlights through librivet

## Expected Results

Envelopes; correct lifecycle (plan T-11).

## Actual Results

The five T-11 tests passed on macOS: exactly the 18 `rivet_*` exports (install name `@rpath`), the C demo shared and static, the Python ctypes demo (request, stream, live input, timeout marker, cancel, highlight), the header equal to `cbindgen` output, and the pkg-config template. Linux: `conformance_ffi` is part of the CI test job, green on ubuntu-latest in run 36505156729 (shared `librivet.so` and static `librivet.a` with the Linux `Libs.private` list); on CI the in-suite header check is skipped before `cbindgen` is installed, and the separate `C header (T-11)` step runs `cbindgen --verify` (green).
