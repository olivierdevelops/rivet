## Procedure

```sh
cargo test --workspace --all-targets --all-features --no-fail-fast   # full run → /tmp/p3-tests.log
cargo test --all-features --test conformance_dag
```

Tests executed (8):

- `conformance_dag::cycles_and_undeclared_reads_are_compile_errors` — `after` cycles are syntax.dag_cycle and reading another node without `after` is syntax.dag, both at compile time with spans
- `conformance_dag::dag_timeout_cancels_running_nodes` — the dag timeout fails with timeout.dag (504 / exit 6), cancels running nodes and skips the rest
- `conformance_dag::diamond_graph` — S44 diamond: the two roots run concurrently and the join starts only after both succeeded, reading their `.result`
- `conformance_dag::fail_fast_is_the_default` — S138 fail fast is the default: the first failure fails the dag; the running sibling is cancelled (its connection closed), never-started nodes are skipped, dependants of the failure are blocked
- `conformance_dag::fail_independent_keeps_independent_results` — S46 fail independent: the independent node succeeds, the failed node's descendant is blocked, and every node name is a {status, result, error} envelope with `.result` null unless succeeded
- `conformance_dag::fan_out_respects_the_limit` — fan-out: independent nodes are capped by `dag limit N`, every node succeeds and results keep declaration order
- `conformance_dag::map_fan_out_is_bounded_and_ordered` — S47 bounded `map` fan-out: at most `limit` calls in flight, results in input order
- `conformance_dag::nodes_call_nested_requests` — a pure dag computes node values in dependency order; nodes may call operations that run their own nested dag

v0.1.0 run: `cargo test conformance_dag`.
