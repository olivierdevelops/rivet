## Test Data

Test fixtures and bundles defined in `tests/conformance_udp.rs` and the shared helpers under `tests/` (in-process servers, temporary directories).

## Procedure

```sh
cargo test --workspace --all-targets --all-features --no-fail-fast   # full run → /tmp/p3-tests.log
cargo test --all-features --test conformance_udp
```

Tests executed (10):

- `conformance_udp::bind_without_listen_grant_is_denied`
- `conformance_udp::connected_ipv4_round_trip` — a connected loopback socket sends one JSON datagram and decodes the reply
- `conformance_udp::connected_ipv6_round_trip_when_available`
- `conformance_udp::demo_08_udp_bundle` — docs/demos/08-udp telemetry.status and telemetry.receive behave as the README describes against local fixtures
- `conformance_udp::denied_peer_sends_nothing` — a denied peer sends zero datagrams
- `conformance_udp::listener_reply_needs_its_own_grant` — a bound listener reports the sender and replies only with that peer's own grant
- `conformance_udp::lost_reply_times_out_without_retry`
- `conformance_udp::multicast_manifest_agrees_with_runtime_permits` — B3: for UDP multicast (default and explicit bind) the manifest's check-policy decision matches the runtime permit (group connect + bind/multicast_join on the bind address) for every grant combination, and agrees for the docs/demos/08-udp bundle
- `conformance_udp::multicast_on_loopback` — multicast joins a group on the loopback interface, receives a datagram and leaves on scope exit
- `conformance_udp::truncated_and_oversized_datagrams` — a reply longer than max_datagram is udp.truncated, an oversized send is refused before sending

v0.1.0 run: `cargo test conformance_udp`.
